# RoguePoison — Project Guide

WoW addon for **Rogues on WoW Forever** only. Shows a bar of the poisons in the
player's bags plus sharpening stones (one icon per type, highest rank in
bags, stack count on the icon). Left-click applies to the main hand,
right-click to the off hand. Warns when poisons, sharpening stones, Flash
Powder or Blinding Powder run low. Poison-crafting reagents are deliberately
not tracked on the bar; instead, with a vendor and the crafting window open,
a buy row above "Create All" buys the reagents for N stacks / N items of the
selected poison.

## Target client

- WoW Forever = the 12.1 Mainline engine with vanilla content (Blizzard game
  type "camelot"). `## Interface: 16001`. It reports `WOW_PROJECT_MAINLINE`, so
  there is no per-flavor code path.
- Use the namespaced 12.1.5 API (`C_Item.*`, `C_AddOns.*`, `C_PaperDollInfo.*`,
  `Settings.*`). Deprecated globals (`GetItemCount`, `GetItemInfo`,
  `GetWeaponEnchantInfo`, `Round`, …) are gone — no `or LegacyGlobal` fallbacks.
- Item IDs are the vanilla ones (`Data/Poisons.lua`).
- Weapon state comes from `C_Item.GetWeaponEnchantInfo(Enum.WeaponSlot.*)`,
  which lists every enchant on the weapon (`hasEnchant`, `timeLeft` ms,
  `charges`). Forever lets a weapon carry a poison and a sharpening stone at
  once; an entry with charges is the poison, one without is the stone.
  `C_PaperDollInfo.GetTemporaryEnchantmentInfo` reports only one enchant, so
  it is not used. Guard reads with `issecretvalue`.

## Directory layout

The outer `RoguePoison/` is the git repo. The inner `RoguePoison/` is the addon
folder that ships; `release.sh` packages only it.

```
RoguePoison/
  RoguePoison.toc
  Libs/            Ace3 (DB, DBOptions, GUI, Config), LDB, LibDBIcon
  Locales/         Locales.lua (registry, ns.L), enUS (fallback), zhCN, zhTW
  Media/icon.tga   in-game icon, generated by art/render.py
  Data/Poisons.lua item types (poisons + sharpening stones) → kind + item IDs, highest rank first; ns.ITEM, ns.ITEM_KIND
  Init.lua         ns setup, module registry, bootstrap, minimap icon, slash
  Config.lua       AceDB defaults (RoguePoisonDB)
  Modules/PoisonBar.lua  the bar, tooltips, low-stock labels
  Modules/ReagentBuyer.lua  vendor buy row on the profession crafting page
  Options.lua      AceGUI settings window + Blizzard Settings entry
tests/poisonbar_spec.lua  stubbed-API spec, no client needed
art/                      icon source (not shipped)
  icon.svg                source, original artwork
  render.py               uv run --no-project --script art/render.py
  curseforge-icon.png     1024x1024 CurseForge project icon
```

The same artwork is the in-game icon: `RoguePoison/Media/icon.tga` (256x256,
32-bit RLE with alpha), used by the `.toc` `IconTexture` and the minimap
button (`ns.ICON`). Edit `art/icon.svg`, then re-run `art/render.py`, which
writes both the PNG and the TGA; never edit either by hand.

## Load order

Libs → Locales → Data → `Init.lua` → `Config.lua` → Modules → `Options.lua`.

## Conventions

- Every file starts with `local addonName, ns = ...`; share state via `ns`, not globals.
- Modules: `ns:RegisterModule(id, M)` and implement `OnDBReady`,
  `OnPlayerLogin`, `Refresh` as needed. `OnPlayerLogin` only runs when the
  player is a Rogue (`ns.active`). No per-module bootstrap frames.
- After changing a setting call `ns:RefreshAll()`.
- Every user-visible string goes through `ns.L[...]`; add the key to all three
  locale files (same key order).
- Localisation is our own registry (`Locales/Locales.lua`), not AceLocale, so
  the language can change at runtime. `ns.L` is a proxy resolving each key
  against the active locale, then enUS, then the key itself — always look keys
  up when rendering, never cache translated text. The choice lives in
  `ns.db.global.locale` (`"auto"` = game client) and is changed through
  `ns:SetLanguage(code)`, which refreshes modules and rebuilds the open settings
  window. Not covered: the AceDBOptions profiles page and the Blizzard Settings
  entry name (follow the client / need `/reload`). Item names always come from
  the client.
- Settings live in `ns.db.profile`; defaults only in `Config.lua`.
  `ns.db.char.seen[type] = itemID` remembers the highest rank seen per poison
  type, so a poison that ran out still shows as a grey 0-count icon.
- No code comments.

## Display rules

- Poisons and sharpening stones are checked separately (`kind` in
  `Data/Poisons.lua`). A weapon needs a poison when it has none, its time left
  is below `timeThreshold` minutes, or its charges are below
  `chargesThreshold`; it needs a stone when it has none or its time left is
  below `timeThreshold` (0 disables a check). Only bladed weapons (axe, sword,
  polearm, dagger) take a stone, so maces and fist weapons are never asked
  for one. A weapon whose enchant data is secret is skipped, not treated as
  empty. Each slot is read once per tick (`slotStates`) and shared by the
  needs check, countdown and tooltip.
- A poison / sharpening stone button shows when unlocked (preview), when it is
  low (count below `poisonThreshold`, 0 included), or when a weapon needs that
  kind and the item is in the bags. A 0-count button is grey and has no click
  action. Unchecking Sharpening Stone in settings drops the stone check.
- The Flash Powder and Blinding Powder icons (not clickable, tooltip only) are
  appended last while tracked (`trackFlash` + Vanish known; `trackBlind` +
  Blind known) and below their threshold (`flashThreshold` / `blindThreshold`);
  unlocked mode previews them while tracked.
- "Low" only applies with `showWarnings` on. A low icon gets a red count and
  the `WARN_LOW_STOCK` label right under it (no item list anywhere). The
  label is 75% of the count font size and wraps within icon size + spacing.
- A live countdown (`container.timer`, same small font size, yellow) sits
  centered under the bar (pushed below `WARN_LOW_STOCK` when any shown icon is
  low) listing each weapon whose poison or stone (tracked kinds only, the
  sooner one) is below `timeThreshold` (e.g. `Main hand 4:59  Off hand 3:12`).
  Empty while unlocked or when no weapon is expiring.
- A hand "can take" an item when it holds a weapon of the right type (any
  weapon for poisons, bladed for stones). Click macros, the tooltip's per-hand
  status and click lines, and the click hint all follow that; the tooltip
  drops a section (and its blank separator) when it has no lines.
- A click hint sits above the bar (`HINT_CLICK_BOTH`, `HINT_CLICK_MAIN` or
  `HINT_CLICK_OFF`, by which hands some shown, in-stock button can apply to),
  same small font size as the low label. It is empty while unlocked or when
  no shown button can be applied.
- The bar is shown whenever it has at least one icon, except in a rest area
  (`IsResting()`, refreshed on `PLAYER_UPDATE_RESTING`); unlocked preview
  still shows there.

## Reagent buyer

- Lives on `ProfessionsFrame.CraftingPage` (`Blizzard_Professions`, load on
  demand), anchored above `CreateAllButton`; recipe changes come from a
  `hooksecurefunc` on `SchematicForm.Init`.
- Shown only while `enabled` is on, a merchant is open, the selected recipe
  is learned, crafts an item of kind `poison` in `ns.ITEM_KIND` (so Blinding
  Powder and sharpening stones are excluded; no vendor sells stone) and every
  basic reagent (`Enum.CraftingReagentType.Basic`) is sold by that merchant
  for gold. That is the "poison vendor" check.
- Two rows stacked above `CreateAllButton`, left edges aligned with it
  (stacks on top, items below), each `[box] unit [Buy] cost`; the Buy
  buttons line up at the widest unit label. The cost after the button is the
  coin string of the plan, red with `BUY_NO_GOLD` when the player cannot
  afford it (button disabled; `PLAYER_MONEY` refreshes), empty when nothing
  is to be bought.
- N stacks = N x item max stack, N items as typed; amounts in
  `ns.db.profile.buyAmount`. Buys only what the bags lack, rounded up to the
  vendor bundle (`stackCount`), capped per call at `GetMerchantItemMaxStack`.
  Purchases go one at a time, the next after `BAG_UPDATE_DELAYED` shows the
  last. A purchase red error (`ERR_INV_FULL`, `ERR_BAG_FULL`,
  `ERR_ITEM_MAX_COUNT`, `ERR_NOT_ENOUGH_MONEY`, `ERR_VENDOR_SOLD_OUT`,
  `ERR_VENDOR_TOO_FAR`; other red errors are ignored), a `MERCHANT_UPDATE`
  that moves the item being bought off its merchant index, or closing the
  merchant stops the run and prints `BUY_STOPPED`. No timeout. A vendor whose limited stock (`numAvailable`) cannot cover
  the plan disables that button and its tooltip says `BUY_OUT_OF_STOCK`. The
  button tooltip lists what will be bought, and is redrawn on every update
  while hovered; it is hidden when the plan cannot be computed or the panel
  hides.
- A missing max stack size (stacks row) or reagent name (tooltip) calls
  `C_Item.RequestLoadItemDataByID` once per item; a successful
  `ITEM_DATA_LOAD_RESULT` refreshes the panel once, only while the panel is
  shown. A failed load is not requested again.
- A focused amount box holding an invalid value (empty or below 1) disables
  its own Buy button; losing focus restores the saved amount. Clicking either
  Buy button first clears focus from both boxes.

## Combat lockdown

The poison buttons are `SecureActionButtonTemplate` with
`type1/macrotext1 = "/use item:<id>\n/use 16"` and `type2/macrotext2 … /use 17`,
each set only when that hand can take the item.
The bar container therefore counts as protected: positioning, size,
attributes and Show/Hide happen only out of combat (`M:ApplySecure`). In combat
those changes set `pendingSecure` and are applied on `PLAYER_REGEN_ENABLED`.
Count text and low-stock labels are plain font strings and update any time
(labels are emptied with `SetText("")`, never hidden).

Everything is hidden in combat: the bar is a child of a
frame driven by `RegisterStateDriver(..., "visibility", "[combat] hide; show")`.
The settings window closes on `PLAYER_REGEN_DISABLED` and reopens on the same
tab, with the same lock state, on `PLAYER_REGEN_ENABLED`; `ns:OpenOptions`
called in combat is deferred the same way.

## Testing

- `lua tests/poisonbar_spec.lua` — loads the addon against stubbed WoW APIs and
  checks visibility, click macros, low-stock labels and that no protected call happens
  in combat. Extend it when changing `PoisonBar.lua`.
- `luac -p` every changed Lua file.
- In game: `/rpoison` opens settings, `/rpoison unlock|lock|reset`.

## Release workflow

Releases are cut through `/release` (`.claude/commands/release.md`, mirrored
for Codex at `.agents/skills/source-command-release/SKILL.md`; both local and
gitignored). The `## Version:` in the `.toc` is always the next unreleased
version. `bash release.sh` builds `RoguePoison-v<version>.zip`.

Test builds go through `/beta` (`.claude/commands/beta.md`, mirrored at
`.agents/skills/source-command-beta/SKILL.md`): runs the checks and
`bash release.sh --beta` → `RoguePoison-v<version>-beta.zip`, with no
CHANGELOG edit, commit, tag or version bump. Do **not** push
unless asked; uploads to CurseForge/WoWInterface are manual.
